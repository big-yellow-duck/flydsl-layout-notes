Scope, assumptions, and source references
The 2D view models the BLOCK_K outer loop, with an optional preview of the next global-to-register prefetch. Its C highlight denotes the accumulator’s output region: the kernel does not write C each iteration. In split-K, the completed partial is published first and a last-arriving thread finalizes its output slots. The scalar probe is mathematical, not a lane mapping. This explorer reproduces the indexing in lessons/01-gpu-programming/13-matmul/10b-cache-policy/solution.py, inspected on 16 November 2026; source-file blob SHA 0277d7e841de9717806eba115447c0dcbb85f4fe. Teaching presets are illustrative, not measured tuning results. The three 10b presets come from CONFIGS_BY_SHAPE. The implementation is a standalone integer model, not a FlyDSL execution trace or hardware simulator.
The mapping requires complete physical tiles and complete M groups. K partitions must contain complete BLOCK_K tiles. Amber warnings distinguish mathematically valid layout settings from settings rejected by 10b’s kernel validator. A tile group can contain more than one WMMA wave when WAVE_GROUPS = 1; in 10b, multiple independent groups each contain one wave32.
Changing traversal does not change row-major workspace tile IDs. Workspace numbers identify a tile’s FP32 partial region; they do not describe the thread/fragment arrangement inside that region. Cache policy modifiers do not change this launch mapping. Cache reuse is an opportunity, not a guarantee; LDS slices remain separate per tile group.
